# Windows 11 新机开荒范围清单 v2

日期：2026-09-03
相对 v1 的变化：
1. 删除所有"过深、效果细微、争议大"的项（见第 6 节删除清单）。
2. 微软服务与预装应用默认全部保留，不做卸载；仅"推送/广告"类提供可选关闭，默认不标推荐。
3. 软件模块改为"官方网站入口 + 推荐安装路径"，不集成安装包，不调用 winget。
4. 新增"磁盘与路径"为核心模块：磁盘检测、分盘建议、目录骨架、用户文件夹迁移、缓存类环境变量迁移、安装引导、C 盘大文件治理。

## 1. 模块总览与执行顺序

| 序 | 模块 | 目标 | 权限 |
|---|---|---|---|
| 0 | 探测 | 硬件、磁盘/分区、OEM、MDM、代理、OneDrive、已装工具 | 普通 |
| 1 | 磁盘与路径 | 把"东西不进 C 盘"这件事一次做完 | 分区需管理员，其余大多普通 |
| 2 | 系统设置 | 界面、交互、中文输入法，少量可选去推送 | 普通（HKCU） |
| 3 | 软件入口 | 官方下载页目录 + 每款软件的推荐安装路径 | 普通 |
| 4 | 收尾 | 还原点、变更报告、需重启项、后续手动项清单 | 管理员（还原点） |

交互流程（v2，不再是问卷向导）：启动即探测 → 主页面按分类列出全部条目，每条显示当前值 → 目标值、状态与风险标签 → 用户点哪一项就执行哪一项 → 就地重新 Detect 刷新状态。执行记录、软件入口、C 盘治理为可返回的子页。

## 3. 磁盘与路径模块（核心）

### 3.1 磁盘检测与分盘建议

规则表（首版，按物理盘数与容量）：

| 场景 | 建议 |
|---|---|
| 单盘 ≤ 256GB | 不分区。只做路径引导与缓存迁移到 C 盘下的统一目录（避免散落） |
| 单盘 512GB | C 160–180GB，其余为 D |
| 单盘 1TB | C 200–250GB，其余为 D |
| 单盘 2TB+ | C 250–300GB，D 其余；不建议再切 E |
| 双盘（系统 SSD + 数据盘） | 系统盘不分区整块做 C；数据盘整块做 D |
| 已有 D/E | 不动分区，仅识别"数据盘"（容量最大且非系统的卷）作为默认目标 |

执行策略：
- **建议为主，执行为辅**。仅当满足全部前置条件时提供"一键压缩 C 并新建 D"：全新机（安装日期 ≤ 30 天）、C 盘已用 < 80GB、`Get-PartitionSupportedSize` 允许的压缩量 ≥ 建议 D 大小、非 MDM 管控。
- 不满足则只给出建议数字，并跳转"磁盘管理"，附操作说明。
- 永远不删除、不移动、不合并已有分区。
- 分区前强制创建还原点，并提示备份。

本机对照：已分三区，工具应识别 D（452GB，剩 139GB）为数据盘，不给分区建议。

### 3.2 目录骨架（在数据盘一次建好）

建议结构（可改名，写入 Profile 供后续所有模块引用）：

```
D:\
├─ Applications\        # 所有第三方软件安装目录
├─ DevCache\            # 各语言包管理器缓存（见 3.4）
├─ Data\                # 用户文件夹迁移目标（Documents/Downloads/Pictures/Videos/Music）
├─ Temp\                # TEMP/TMP
├─ Models\              # Ollama / HuggingFace 等大模型文件
├─ VMs\                 # Docker/WSL/VMware 磁盘镜像
└─ Games\               # 游戏平台库
```

本机对照：已自建 `D:\Applications`、`D:\DevCache`、`D:\123\{Documents,...}`、`D:\Ollama\models`、`D:\AndroidSDK`、`D:\AndroidAVD`、`D:\JDK1.8`、`D:\Vmware`。结构与建议一致，工具应识别已有目录并直接复用，而不是新建一套。

### 3.3 用户文件夹与 TEMP 迁移

| 项 | 实现 | 本机 | 动作 |
|---|---|---|---|
| Documents / Downloads / Pictures / Videos / Music | `SHSetKnownFolderPath` + 移动内容 + `SHChangeNotify` | 已在 D:\123\ | 已完成则跳过 |
| Desktop | 同上，但若被 OneDrive 接管则先要求用户在 OneDrive 设置中停止桌面备份（工具只跳转，不改 OneDrive） | 在 OneDrive 下，KFM=512 | 默认不推荐迁移桌面；被 KFM 接管时该条标为不适用并说明原因 |
| TEMP / TMP（用户级） | 环境变量 User 作用域 → `D:\Temp` | C 盘，6.4GB 堆积 | 默认迁移 |
| TEMP / TMP（系统级） | Machine 作用域，需管理员 | C:\WINDOWS\TEMP | 可选，默认不动 |

| conda | `.condarc` 的 `envs_dirs` / `pkgs_dirs`；只在没有 `.condarc` 时自动写入，已有则给手动步骤 | DevCache\conda\{envs,pkgs} | 已配置 |

### 3.5 安装引导（不装 C 盘）

第三方安装程序无法被外部强制改路径，工具能做的是把"记得改路径"变成零成本动作：
- 建好 `D:\Applications` 并固定到资源管理器快速访问。
- 软件入口页每一项旁显示推荐路径，一键复制，如 `D:\Applications\7-Zip`。
- 标注哪些安装器不支持自定义路径（如部分 Electron 应用默认装 `%LOCALAPPDATA%\Programs`），并给出该应用的替代方法（可用参数 `/D=` 或安装后不可迁移）。
- 微软商店"新应用保存位置"无公开接口，软件入口页底部的"商店应用保存位置"按钮跳到 `ms-settings:savelocations`（设置 → 存储 → 高级存储设置 → 新内容的保存位置），由用户自己把"新的应用将保存到"改成数据盘。

### 3.6 C 盘大文件治理（检测 + 建议，多数只提示）

| 项 | 本机 | 动作 |
|---|---|---|
| hiberfil.sys | 6.3GB（已是精简模式） | 笔记本默认保留（不标推荐）；台式机点"关闭休眠"条目执行 `powercfg /h off` |
| pagefile.sys | 7.8GB，C 盘 | 只提示（迁移需重启且易误配） |
| 用户 Temp | 6.4GB | 迁移后一次性清理旧目录（仅删除 7 天前文件） |

| Windows\Installer、Package Cache | 8.7GB + 2.2GB | 不动（删除会破坏卸载/修复） |
| 存储感知 | 已开 | 默认开启，频率"磁盘空间不足时" |
| AppData 大户列表（>1GB） | Claude 10GB、NVIDIA 7.6、JetBrains 7、Docker 4.3、.codex 3.4 等 | 展示列表，逐项给出"可迁移 / 可清理 / 保留"标签 |

### 4.4 只提示不执行（"检查项"子页）

六项全部只读，工具只给结论与跳转按钮，不代改任何设置。不进启动探测（WMI 查询偏慢且与主列表无关），进入检查项页时按需采集。

| 项 | 检测方式 | 判定 | 跳转 |
|---|---|---|---|
| BitLocker 恢复密钥 | `Win32_EncryptableVolume` 的 `ProtectionStatus`（系统盘） | 已加密则警告：确认恢复密钥已备份到本机以外 | `ms-settings:deviceencryption` |
| 多套杀软并存 | `root\SecurityCenter2` 的 `AntiVirusProduct` | 非 Defender 的产品 > 1 套时警告 | `ms-settings:appsfeatures` |

| 区域与时区 | `RegionInfo` / `CultureInfo` / `TimeZoneInfo` | 只展示当前值，不做任何假设 | `ms-settings:dateandtime` |

OEM 匹配只用 Publisher 不用 DisplayName：用名字匹配会把 MSI Afterburner、`vs_*msi` 这类无关条目一起圈进来。本机实测由 22 条误报收敛到 5 条真实预装。

## 7. 交互模型（v2：取消问卷）

v1 的 5 题问卷已删除。原因是每一题的答案都只能变成"要不要做某几项"，而这几项在列表里本来就逐条可见、可单独执行，先问一遍再生成方案属于多一层间接。现在只保留两个真正需要用户决定的输入：

| 输入 | 位置 | 影响 |
|---|---|---|
| 数据盘 | 头部下拉，按探测结果预填 | 全部路径、缓存、目录骨架类条目的目标盘；改了立即重新 Detect 全部条目 |
| 是否按建议分区 | "分区"分类里的条目，执行前二次确认 | 单盘无数据分区时才出现；成功后重新探测整机，路径类条目自动出现 |

原来问卷第 1 题（用途）没有替代物：软件入口页改用固定分类顺序（基础工具 → 浏览器 → 通讯 → 办公 → 媒体 → 开发 → 游戏 → 运行库），目录骨架固定建全部 7 个目录。第 3、4、5 题对应的界面风格、中文输入法、去推送条目全部列在主页面，只是不标"推荐"，用户按需点执行。
