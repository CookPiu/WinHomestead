# Windows 11 新机开荒范围清单 v2

日期：2026-09-03
相对 v1 的变化：
1. 删除所有"过深、效果细微、争议大"的项（见第 6 节删除清单）。
2. 微软服务与预装应用默认全部保留，不做卸载；仅"推送/广告"类提供可选关闭，默认不标推荐。
3. 软件模块改为"官方网站入口 + 推荐安装路径"，不集成安装包，不调用 winget。
4. 新增"磁盘与路径"为核心模块：磁盘检测、分盘建议、目录骨架、用户文件夹迁移、缓存类环境变量迁移、安装引导。
5. 不做 C 盘大文件扫描与治理：开荒面对的是全新机器，没有存量垃圾可清；扫描旧机的 AppData 属于清理工具的事，不在本工具范围内。系统盘只保留"空间清理"分类的三条可执行项（见 3.6）。

2026-09-11 增补（来源与取舍依据见 `05-开荒操作资料汇编.md`）：

6. 新增 Dev Drive 建议条目（3.7）。只检测与给建议，永远不格式化任何卷。
7. 开发缓存预设补 Maven 与 vcpkg，并更正 v2 里"Maven 没有环境变量入口"的错误判断（3.4）。
8. 检查项由六项扩到十项，新增还原点占用、开机启动项、屏幕刷新率、电池健康（4.5）。

## 1. 模块总览与执行顺序

| 序 | 模块 | 目标 | 权限 |
|---|---|---|---|
| 0 | 探测 | 硬件、磁盘/分区、OEM、MDM、代理、OneDrive、已装工具 | 普通 |
| 1 | 磁盘与路径 | 把"东西不进 C 盘"这件事一次做完 | 分区需管理员，其余大多普通 |
| 2 | 系统设置 | 界面、交互、中文输入法，少量可选去推送 | 普通（HKCU） |
| 3 | 软件推荐 | 官方下载页入口 + 按分类规划好的建议安装路径 | 普通 |
| 4 | 收尾 | 还原点、变更报告、需重启项、后续手动项清单 | 管理员（还原点） |

交互流程（v2，不再是问卷向导）：启动即探测 → 主页面按分类列出全部条目，每条显示当前值 → 目标值（人话，不是注册表键值）、状态与风险标签 → 用户点哪一项就执行哪一项 → 就地重新 Detect 刷新状态。左栏第一项固定是“这台电脑”，显示硬件与系统信息（容量给精确值，不四舍五入）。执行记录、软件推荐、检查项为可返回的子页。

## 2. 探测层（只读）

| 探测项 | 用途 |
|---|---|
| 物理盘数量、类型、容量；分区布局；各卷剩余 | 分盘建议、路径迁移目标盘、是否隐藏整个路径模块 |
| 台式/笔记本、CPU、内存（字节原值） | 休眠文件策略、页面文件提示；“这台电脑”栏位展示 |
| OEM 厂商 | 机器摘要显示厂商与型号；厂商名同时用于检查项页筛 OEM 预装软件（见 4.5） |
| MDM/域 | 检测到则跳过所有 HKLM 类改动，仅提示 |
| 系统代理 | 打开官网链接与后续下载走代理 |
| OneDrive 是否登录、KFM 接管了哪些文件夹 | 决定桌面能否迁移 |
| 已装开发工具（pip/npm/pnpm/conda/Gradle/Maven/NuGet/Cargo/Go/Flutter/Android/Ollama/Docker 等） | 决定“预设开发缓存”跳过哪些项；已装的工具不动 |
| 已设置的路径类环境变量 | 已设过的变量不覆盖 |

下文各节的"参考机"指开发时用来对照的一台真实机器：单块 1 TB NVMe（GPT，已分三区）、笔记本、32 GB 内存、OneDrive 已登录并接管桌面、已装大量开发工具、受设备管理策略约束。它代表的是"已经用起来的机器"这一类场景，与开荒工具真正面向的全新机器正好相反，拿来验证"已满足"和"不适用"两条分支最合适。

## 3. 磁盘与路径模块（核心）

### 3.1 磁盘检测与分盘建议

规则表（首版，按物理盘数与容量）：

| 场景 | 建议 |
|---|---|
| 单盘 ≤ 256GB | 不分区。只做路径引导与缓存迁移到 C 盘下的统一目录（避免散落） |
| 单盘 512GB | C 160–180GB，其余为 D |
| 单盘 1TB | C 200–250GB，其余为 D |
| 单盘 2TB+ | C 250–300GB，D 其余；不建议再切 E |
| 双盘（系统 SSD + 数据盘） | 系统盘不分区整块做 C；数据盘整块做 D |
| 已有 D/E | 不动分区，仅识别"数据盘"（容量最大且非系统的卷）作为默认目标 |

执行策略：
- **建议为主，执行为辅**。仅当满足全部前置条件时提供"一键压缩 C 并新建 D"：全新机（安装日期 ≤ 30 天）、C 盘已用 < 80GB、`Get-PartitionSupportedSize` 允许的压缩量 ≥ 建议 D 大小、非 MDM 管控。
- 不满足则只给出建议数字，并跳转"磁盘管理"，附操作说明。
- 永远不删除、不移动、不合并已有分区。
- 分区前强制创建还原点，并提示备份。

参考机对照：已分三区，工具应识别容量最大的非系统卷为数据盘，不给分区建议。

### 3.2 目录骨架（在数据盘一次建好）

建议结构（可改名，写入 Profile 供后续所有模块引用）：

```
D:\
├─ Applications\        # 第三方软件安装目录，下面按分类再分子目录（Tools/Browsers/Chat/Office/Media/Dev/Games/Runtimes）
├─ DevCache\            # 各语言包管理器缓存（见 3.4）
├─ Data\                # 用户文件夹迁移目标（Documents/Downloads/Pictures/Videos/Music）
├─ Temp\                # TEMP/TMP
├─ Models\              # Ollama / HuggingFace 等大模型文件
├─ VMs\                 # Docker/WSL/VMware 磁盘镜像
└─ Games\               # 游戏平台库
```

参考机对照：数据盘上早已手工建好 `Applications`、`DevCache`、用户文件夹目标目录，以及模型、Android SDK、JDK、虚拟机镜像各自的目录。结构与上面的建议基本一致，工具应识别已有目录并直接复用，而不是新建一套。

### 3.3 用户文件夹与 TEMP 迁移

| 项 | 实现 | 参考机 | 动作 |
|---|---|---|---|
| Documents / Downloads / Pictures / Videos / Music | `SHSetKnownFolderPath` + 移动内容 + `SHChangeNotify` | 已在数据盘 | 已完成则跳过 |
| Desktop | 同上，但若被 OneDrive 接管则先要求用户在 OneDrive 设置中停止桌面备份（工具只跳转，不改 OneDrive） | 在 OneDrive 下，KFM=512 | 默认不推荐迁移桌面；被 KFM 接管时该条标为不适用并说明原因 |
| TEMP / TMP（用户级） | 环境变量 User 作用域 → `D:\Temp` | C 盘，6.4GB 堆积 | 默认迁移 |
| TEMP / TMP（系统级） | Machine 作用域，需管理员 | C:\WINDOWS\TEMP | 可选，默认不动 |

TEMP 指向 Dev Drive（见 3.7）是个例外：微软要求这种情况下放行 `WinSetupMon` 过滤器（`fsutil devdrv setfiltersallowed WinSetupMon`），否则会影响 Windows 升级流程。本工具默认把 TEMP 指到普通 NTFS 数据盘，不涉及这条；只有用户自己改到 Dev Drive 上时才需要，因此写在 Dev Drive 条目的手动步骤里。

### 3.4 开发缓存预设（装工具之前做）

开荒工具面对的是"还没装"的机器，所以这一块只做**预设**，不做迁移：在装 Python、Node、JDK 这些工具**之前**，先把它们的缓存目录通过用户环境变量指到数据盘，以后装上什么，缓存直接落在 D 盘。

界面上只有一条"预设开发缓存目录"，一次把下面这些变量写好。跳过规则有两条：变量已经设过的不动（不覆盖用户自己的选择）；对应工具已经装在这台机器上的那一项跳过——改在用工具的缓存位置需要连同已下载的内容一起搬，那是迁移不是开荒，本工具不做。全部工具都已安装时整条标为不适用。

| 变量 | 目标 | 对应工具 |
|---|---|---|
| `PIP_CACHE_DIR` | DevCache\pip-cache | Python / pip |
| `UV_CACHE_DIR` | DevCache\uv-cache | uv |
| `npm_config_cache` | DevCache\npm-cache | npm |
| `npm_config_prefix`（同时追加进用户 PATH） | DevCache\npm-global | npm 全局包 |
| `PNPM_HOME` | DevCache\pnpm | pnpm |
| `YARN_CACHE_FOLDER` | DevCache\yarn-cache | Yarn |
| `GRADLE_USER_HOME` | DevCache\gradle | Gradle |
| `MAVEN_OPTS`（值为 `-Dmaven.repo.local=<路径>`） | DevCache\maven-repo | Maven |
| `NUGET_PACKAGES` | DevCache\nuget-packages | NuGet |
| `VCPKG_DEFAULT_BINARY_CACHE` | DevCache\vcpkg-cache | vcpkg |
| `CARGO_HOME`、`RUSTUP_HOME` | DevCache\cargo、DevCache\rustup | Cargo / rustup |
| `GOPATH`、`GOMODCACHE` | DevCache\go | Go |
| `PUB_CACHE` | DevCache\pub-cache | Flutter / Dart |
| `CONDA_ENVS_DIRS`、`CONDA_PKGS_DIRS` | DevCache\conda\{envs,pkgs} | Conda |
| `HF_HOME` | Models\huggingface | Hugging Face |
| `OLLAMA_MODELS` | Models\ollama | Ollama |

`npm_config_prefix` 必须连 PATH 一起改，否则 `npm -g` 装出来的命令敲不出来。conda 的 `envs_dirs` / `pkgs_dirs` 有同名环境变量且优先级高于 `.condarc`，所以不用去改 YAML。

两条要写进界面说明的副作用：`NUGET_PACKAGES` 的优先级高于 `nuget.config` 里的 `globalPackagesFolder`，会盖掉仓库自带的设置（微软官方因此推荐优先用配置文件，本工具仍用变量，因为开荒阶段还没有仓库）；`MAVEN_OPTS` 是通用的 JVM 参数变量而不是专用路径变量，用户之后往里加参数时要注意别把 `-Dmaven.repo.local` 这段覆盖掉。

不做的（都是"迁移使用中的工具"，超出开荒范围，只在检测到时于执行记录里给一句步骤）：

| 项 | 为什么不做 |
|---|---|
| Android SDK / AVD | 是软件本体与几十 GB 镜像，改变量不会把它们搬过去；装 Android Studio 时选好位置即可 |
| Java `JAVA_HOME` | JDK 是软件本体，装的时候自定义到 Applications\JDK 就行 |
| Scoop `SCOOP` | 必须在装 Scoop 之前设，工具无从判断用户是否打算装 |
| Docker 镜像位置、JetBrains 系统目录、WSL、VS Code、NVIDIA 着色器缓存、微信/QQ 文件夹、浏览器下载目录、Steam 库 | 都要改应用内部设置或搬大体积数据，只在执行记录里给步骤 |

参考机对照：常见包管理器都已安装且多数变量已设，所以这条在参考机上会显示不适用——正是设计意图。

### 3.5 安装引导（不装 C 盘）

第三方安装程序无法被外部强制改路径，工具能做的是把"记得改路径"变成零成本动作：
- 建好 `D:\Applications` 并固定到资源管理器快速访问；软件不平铺在这一层，按分类各占一个子目录（Tools / Browsers / Chat / Office / Media / Dev / Games / Runtimes）。
- 软件推荐页每一项旁显示建议路径并可直接编辑，一键复制，如 `D:\Applications\Tools\7-Zip`。根目录可改，改过的根目录与逐项路径都会记住。
- 标注哪些安装器不支持自定义路径（如部分 Electron 应用默认装 `%LOCALAPPDATA%\Programs`），并给出该应用的替代方法（可用参数 `/D=` 或安装后不可迁移）。
- 微软商店"新应用保存位置"无公开接口，软件推荐页底部的"商店应用保存位置"按钮跳到 `ms-settings:savelocations`（设置 → 存储 → 高级存储设置 → 新内容的保存位置），由用户自己把"新的应用将保存到"改成数据盘。

### 3.6 空间清理（主列表"空间清理"分类，三条可执行项）

| 项 | 实现 | 动作 |
|---|---|---|
| 清理旧临时目录 | 删除用户 Temp 中 7 天前的文件，被占用的跳过 | 默认推荐；配合 3.3 的 TEMP 迁移一次做完 |
| 关闭休眠 | `powercfg /hibernate off` | 台式机可选，笔记本不列出 |
| 存储感知 | StoragePolicy 01=1、2048=0 | 默认推荐，频率"磁盘空间不足时" |

原先的 C 盘大文件治理子页（hiberfil / pagefile / Phone Link 缓存 / AppData 大户扫描）已删除：那是给用了很久的机器做清理，和"新机开荒"的定位不符，扫描本身也要十几秒。pagefile、Windows\Installer 这类本来就只提示不动，去掉后没有功能损失。

### 3.7 Dev Drive（建议，不执行）

Dev Drive 是微软给开发负载准备的 ReFS 卷：卷被标记为受信任后，Defender 在它上面跑 performance mode（异步扫描）而不是实时扫描，源码、包缓存、编译中间产物放在这里读写更快。它与 3.4 是互补关系——3.4 决定缓存"落不落系统盘"，Dev Drive 决定"落下来之后读写快不快、杀软扫不扫"。

关键约束决定了这条只能是建议：**Dev Drive 只能在格式化时指定，已有数据的卷不能就地转换**，重新格式化会清空整个卷。所以条目的形态是检测 + 建议 + 步骤，永远不调用格式化。

| 判定 | 界面表现 |
|---|---|
| 数据盘是 ReFS | 已满足，显示"已经是 Dev Drive"；信任状态提示用 `fsutil devdrv query <盘符>:` 自查 |
| 数据盘是 NTFS，且磁盘上有 ≥ 50 GB 未分配空间 | 建议用未分配空间新建一个 Dev Drive |
| 数据盘是 NTFS，无足够未分配空间 | 建议在数据盘上新建 VHDX（动态扩展，≥ 50 GB）作为 Dev Drive |
| MDM 管控 | 列出但标不适用：企业环境下要管理员在组策略里放开才能创建 |
| 内存 < 8 GB 或 Build < 22621 | 不列出（官方前置条件不满足） |

判定用文件系统名而不是专门的 Dev Drive API：Windows 11 客户端只有"创建开发驱动器"这一条路径能格式化出 ReFS 卷，所以 ReFS 即 Dev Drive 在消费端成立；信任状态另有 `fsutil` 可查，需要管理员，不放进探测。

手动步骤里会一并提醒三件事：开发工具与 SDK 本体仍装在系统盘（官方建议）、缓存目录可以把 3.4 的根目录改到新盘符、TEMP 若要指过去需先放行 `WinSetupMon`。

参考机对照：数据盘是 NTFS 且已有数据，磁盘上没有未分配空间，加上设备受管理策略约束，这条会显示为不适用并给出原因。

### 4.4 显卡（单独一个分类，唯一的 HKLM 设置项）

| 项 | 实现 | 条件 |
|---|---|---|
| GPU 硬件加速调度（HAGS） | `GraphicsDrivers\HwSchMode=2` | 该值不存在说明显卡或驱动不支持，标不适用；MDM 管控时不列出；需管理员，重启后生效 |

这是系统设置模块里唯一写 HKLM 的条目，因此单独成类。v1 的删除清单里曾把它列为"过深"，M3 阶段重新评估后实现了：它在设置界面里本来就有开关（设置 → 显示 → 显示卡），值的含义明确、可回滚，不属于注册表玄学。同批被判"过深"的游戏模式、Modern Standby 断网、Win32PrioritySeparation 维持不做。

### 4.5 只提示不执行（"检查项"子页）

十项全部只读，工具只给结论与跳转按钮，不代改任何设置。不进启动探测（WMI 查询偏慢且与主列表无关），进入检查项页时按需采集。

| 项 | 检测方式 | 判定 | 跳转 |
|---|---|---|---|
| BitLocker 恢复密钥 | `Win32_EncryptableVolume` 的 `ProtectionStatus`（系统盘） | 已加密则警告：确认恢复密钥已备份到本机以外 | `ms-settings:deviceencryption` |
| 多套杀软并存 | `root\SecurityCenter2` 的 `AntiVirusProduct` | 非 Defender 的产品 > 1 套时警告 | `ms-settings:appsfeatures` |
| Windows Update | `Win32_QuickFixEngineering` 最近的 `InstalledOn`（旧注册表键兜底） | ≥ 30 天未打补丁则警告。工具不联网，不代查更新 | `ms-settings:windowsupdate` |
| 还原点占用 | 系统 Build 与系统卷容量 | 26H2（Build 26300）起 Point-in-time restore 默认开启，系统卷 ≥ 200 GB 自动启用，最多占 50 GB、保留 72 小时。没有公开接口能读它的开关与实际占用，只说明会不会被自动打开 | `ms-settings:recovery` |
| 开机启动项 | `Win32_StartupCommand` | 列出随开机启动的程序，≥ 8 项时警告。只覆盖 Run 键与"启动"文件夹，不含任务计划与服务 | `ms-settings:startupapps` |
| 屏幕刷新率 | `EnumDisplaySettings` 取当前模式，并在同分辨率下找最大刷新率 | 当前值低于该分辨率支持的最大值则警告（高刷屏出厂跑 60 Hz 是常态） | `ms-settings:display-advanced` |
| 电池健康 | `root\WMI` 的电池类，缺设计容量时回退 `powercfg /batteryreport /xml` | 满充/设计容量 < 80% 时警告；台式机标不适用。新机统计样本不足，文案说明需正常使用几天再看 | 无 |
| OEM 预装软件 | Uninstall 键的 **Publisher** 匹配 OEM 厂商名 | 列出命中的条目，用不上的自行卸载 | `ms-settings:appsfeatures` |
| 默认应用 | 读 `UrlAssociations\https\UserChoice` 的 ProgId | 只展示当前默认浏览器关联，按类型逐项设置无公开接口 | `ms-settings:defaultapps` |
| 区域与时区 | `RegionInfo` / `CultureInfo` / `TimeZoneInfo` | 只展示当前值，不做任何假设 | `ms-settings:dateandtime` |

OEM 匹配只用 Publisher 不用 DisplayName：用名字匹配会把 MSI Afterburner、`vs_*msi` 这类无关条目一起圈进来。参考机实测由 22 条误报收敛到 5 条真实预装。

## 5. 软件推荐模块

形态：先规划安装目录，再列分类卡片。页面顶部是一个可编辑的根目录（默认 `<数据盘>\Applications`）和“恢复默认”；每个分类有一句话说明它值不值得装，每项显示官网下载页链接（打开系统默认浏览器）、可编辑的建议安装路径（一键复制）、是否支持自定义路径、本机是否已安装（注册表 Uninstall 检测）。

定位是推荐不是清单：文案明确“按需要挑，不用照单全装”，不下载、不静默安装、不内置任何安装包、不改默认程序。用户改过的路径会记住并标“自定义路径”，改回默认值即自动取消记忆。

| 分类 | 条目（首版） |
|---|---|
| 基础工具 | 7-Zip、PowerToys、Everything、Snipaste |
| 浏览器 | Chrome、Firefox |
| 通讯 | 微信、QQ、钉钉、飞书、Telegram |
| 办公 / 笔记 | WPS、Typora、Obsidian |
| 媒体 | PotPlayer、VLC、OBS |
| 开发 | VS Code、Git、Windows Terminal、Python、Node.js、JDK、Docker Desktop、JetBrains Toolbox |
| 游戏 | Steam、Epic |
| 运行库 | VC++ AIO、.NET Desktop Runtime |

目录以 JSON 存放，仅含名称、官网 URL、分类、默认子目录名、安装器类型（决定路径提示文案）。

## 7. 交互模型（v2：取消问卷）

v1 的 5 题问卷已删除。原因是每一题的答案都只能变成"要不要做某几项"，而这几项在列表里本来就逐条可见、可单独执行，先问一遍再生成方案属于多一层间接。现在只保留两个真正需要用户决定的输入：

| 输入 | 位置 | 影响 |
|---|---|---|
| 数据盘 | 头部下拉，按探测结果预填 | 全部路径、缓存、目录骨架类条目的目标盘；改了立即重新 Detect 全部条目 |
| 是否按建议分区 | "分区"分类里的条目，执行前二次确认 | 单盘无数据分区时才出现；成功后重新探测整机，路径类条目自动出现 |

原来问卷第 1 题（用途）没有替代物：软件推荐页改用固定分类顺序（基础工具 → 浏览器 → 通讯 → 办公 → 媒体 → 开发 → 游戏 → 运行库），目录骨架固定建全部 7 个目录。第 3、4、5 题对应的界面风格、中文输入法、去推送条目全部列在主页面，只是不标"推荐"，用户按需点执行。
