## 1. 目标与约束

| 约束 | 设计响应 |
|---|---|
| 下载即运行、体积小 | .NET Framework 4.8（Win11 自带）+ 单 exe，目标 < 10 MB |
| 高效可靠、只留核心 | 任务全部为 C# 类，无脚本；每个任务幂等，Detect 先行 |
| 可预览、可校验 | Detect → Plan → Apply → Verify 四段式；执行前展示 diff |
| 视觉简约流畅 | WPF + WPF-UI（Fluent、Mica、NavigationView 过渡） |
| 微软服务默认保留 | 去推送组默认不勾选；不含任何卸载/禁服务任务 |
| 一次提权 | manifest `requireAdministrator`，启动时校验 HKCU 归属 |

## 2. 技术栈

| 层 | 选择 | 版本约束 |
|---|---|---|
| 运行时 | .NET Framework 4.8，SDK 风格 csproj，`LangVersion` latest | 需 `PolySharp` 提供 `IsExternalInit`、`required` 等 polyfill |

## 4. 核心数据模型

全部为不可变 record，JSON 持久化到 `%ProgramData%\WinHomestead\`。

### 4.1 EnvironmentSnapshot（探测结果）

```csharp
public sealed record EnvironmentSnapshot(
    string OsVersion, string DisplayVersion, int Build, bool IsWindows11,
    bool IsLaptop, long RamBytes, CpuInfo Cpu, string Manufacturer, string Model,
    bool IsMdmEnrolled, bool IsDomainJoined, bool ProxyEnabled,
    IReadOnlyList<DiskInfo> Disks, IReadOnlyList<VolumeInfo> Volumes,
    string SystemDrive, string? DataDrive, DateTime InstallDate,
    OneDriveInfo OneDrive, GpuInfo Gpu,
    IReadOnlyDictionary<string, string> KnownFolders,
    IReadOnlyDictionary<string, string> UserEnvironment,
    IReadOnlyList<DetectedTool> Tools,
    DateTime TakenAt);
```

- `DataDrive`：非系统卷中容量最大者；无则为 null，触发分盘建议。
- `Tools`：`{ Id, Name, Installed, ConfiguredPath }`，Id 与 `env.*` 任务一一对应。
- 容量一律存字节原值（`RamBytes`、`DiskInfo.SizeBytes`、`VolumeInfo.SizeBytes/FreeBytes`），取整只发生在展示层，且一律保留两位小数并附字节数——四舍五入到整数会让 31.43 GB 显示成 32 GB，与任务管理器对不上。
- `Cpu`：`{ Name, Cores, LogicalProcessors }`，来自 `Win32_Processor`，多路时名称取第一颗、核心数求和。

public sealed record Answers(

## 5. 任务接口

```csharp
public interface ITask
{
    TaskMetadata Metadata { get; }
    bool IsApplicable(EnvironmentSnapshot s, Answers a);          // 是否出现在方案中
    bool DefaultChecked(EnvironmentSnapshot s, Answers a);        // 是否标“推荐”
    DetectResult Detect(TaskContext ctx);                          // 当前值 / 目标值 / 是否已满足
    void Apply(TaskContext ctx);                                   // 修改，所有写操作经 ctx 记 journal
    bool Verify(TaskContext ctx);                                  // 重新读取确认
    void Rollback(TaskContext ctx, IReadOnlyList<JournalEntry> entries);
}

public sealed record TaskMetadata(
    string Id, string Module, string DisplayName, string Description,
    RiskFlags Risk, IReadOnlyList<string> DependsOn, int Order);

public sealed record DetectResult(bool Satisfied, string? CurrentValue, string? TargetValue, string? Reason = null);

public sealed class TaskContext
{
    public EnvironmentSnapshot Snapshot { get; }
    public Answers Answers { get; }
    public IRegistry Registry { get; }          // 写操作自动记 journal
    public IEnvironment Environment { get; }
    public IShell Shell { get; }
    public IStorage Storage { get; }
    public IFileSystem FileSystem { get; }      // 目录创建记 journal；文件删除不可撤销
    public IPower Power { get; }                // 休眠开关，写操作记 journal
    public IJournal Journal { get; }
    public ILogger Log { get; }
    public CancellationToken Cancellation { get; }
    public IList<string> ManualSteps { get; }   // 任务可追加"手动项"进入报告
}
```

约定：
- `Detect` 不得有副作用。
- `Apply` 只做一件事；需要多步的拆成多个任务并用 `DependsOn` 串联。
- 键不存在且不适用于当前版本时，`Detect` 返回 `Satisfied=false, Reason="not_applicable"`，Planner 据此标为 NotApplicable。
- 任务 Id 采用 `模块.名称` 小写点分，与《02》任务库索引一致。

`TaskCatalog` 以静态列表注册全部任务；不做反射扫描，便于裁剪与审计。

## 6. Planner 与 TaskRunner

### 6.1 Planner

```
foreach task in Catalog (按 Order 排序)
  if !IsApplicable → 不进入 Plan
  d = Detect
  state = d.Reason == "not_applicable" ? NotApplicable : d.Satisfied ? Skipped : Planned
  checked = state == Planned && DefaultChecked
  emit PlanItem
```

依赖规则在两处生效：`PlanEditor.Normalize` 保证父项仍需执行时子项不标“推荐”；执行时 `SessionRunner.ChainFor` 沿 `DependsOn` 把仍为 Planned 的祖先一起带上。父项 Skipped 视为满足，不阻断子项。

### 6.2 TaskRunner

- 输入：Plan 中 `Checked && State == Planned` 的项，按 `Order` 排序并做拓扑校验。
- 每项：`Apply → Verify`；Verify 失败或 Apply 抛错 → `Rollback(journal 中该任务条目)` → Outcome = RolledBack / Failed。
- 失败不中断，继续下一项。
- `NeedsExplorerRestart` 的任务在组末统一重启一次 Explorer（Runner 收集标志，在最后一个此类任务完成后执行）。
- `NeedsReboot` 汇总到 `ExecutionResult.RebootRequired`。
- 取消：`CancellationToken` 只在任务边界检查；当前任务完成后停止，结果标 `Aborted`。`HomeViewModel` 每次执行建一个 `CancellationTokenSource`，执行期间进度行旁显示“停止”按钮，点了只置取消位，不打断正在写入的任务。
- 进度通过 `IProgress<RunnerProgress>` 回传 UI。

### 6.3 逐项执行与收尾

`SessionRunner`（每个应用会话一个实例）负责逐项执行：
- `Run(taskId)`：取该项及其在列表中仍为 Planned 的祖先依赖，组成子方案交给 `TaskRunner`（`restartExplorer=false`）；Apply → Verify → 失败回滚的规则不变。
- 还原点只在会话第一次执行前创建一次；失败仅告警。
- 整个会话共用 `journal-<session>.jsonl`，每次执行后把累计结果写到 `result-<session>.json`；执行期间 `state.json pendingResume=true`。
- `NeedsExplorerRestart` / `NeedsReboot` 只记标志，界面用提示条让用户选择何时重启资源管理器或电脑。
- 执行结束后界面重新 `Detect` 全部条目并就地刷新；分区类任务执行后重新探测整机。

`ExecutionCoordinator` 只保留跨会话部分：`LoadLast()` 读取上次记录；`--resume`（RunOnce 拉起）时 `Reverify()` 对“需重启”项重新 Verify 并先展示上次记录；上次进程在执行中退出时启动只提示用户检查记录，不再自动续跑（单项执行没有“剩余项”的概念）。

Dev Drive（UC-05b）：`disk.devdrive` 是 `PromptOnly` 条目，`Detect` 用 `IStorage.FileSystemOf` 判 ReFS、用 `LargestFreeExtent` 决定建议哪种载体，`Apply` 只写手动步骤，`Verify` 恒为 true。内存或系统版本不满足官方前置条件时 `IsApplicable` 返回 false 直接不列出；MDM 则列出并在 `Detect` 里标不适用——环境限制要让用户看到原因，硬件不满足没必要占一行。工具不提供 `Format-Volume -DevDrive`，因为它会清空目标卷。

分区（UC-05）：`disk.shrink_and_create` 在单盘无数据分区且非 MDM 时列出（不标推荐）；`Detect` 里用 `IStorage.GetSupportedSize` 复核可压缩量 ≥ 建议 D 的 80%，不满足标 NotApplicable 并给原因。执行前界面二次确认。`path.skeleton` 依赖它，因此在没有数据盘时路径类条目不出现，分区成功后重新探测自动出现。分区不可撤销，`Rollback` 只写手动项。Storage WMI 的方法调用需要管理员。

## 7. 原生层封装

| 接口 | 实现要点 |
|---|---|
| `IRegistry` | `Microsoft.Win32.Registry`；`Set` 前读旧值写 journal；支持 `DWORD/QWORD/String/ExpandString/Binary`（Binary 在 journal 里按十六进制存原值）；`DeleteValue` 同样记录 |
| `IEnvironment` | 读写 `HKCU\Environment`（User）与 `HKLM\...\Session Manager\Environment`（Machine）；写后 `SendMessageTimeout(HWND_BROADCAST, WM_SETTINGCHANGE, "Environment")` |
| `IShell.SetKnownFolder` | `SHSetKnownFolderPath(guid, 0, IntPtr.Zero, path)`；先创建目标；返回 HRESULT 转异常；随后 `SHChangeNotify(SHCNE_ASSOCCHANGED)` |
| `IShell.MoveContents` | `Directory.EnumerateFileSystemEntries` 逐项 `Move`；同名跳过并记录；失败抛出并附已移动列表 |
| `IShell.RestartExplorer` | 结束所有 `explorer.exe` 后 `Process.Start("explorer.exe")`；等待 Shell 窗口出现 ≤ 5 s |
| `IShell.PinToQuickAccess` | `Shell.Application`（IDispatch 反射调用，不用 dynamic）：`NameSpace(path).Self.InvokeVerb("pintohome")`；是否已固定用主文件夹命名空间 `{679f85cb-…}` 枚举并检查 `System.Home.IsPinned` |
| `IPower` | 休眠：读 `HKLM\...\Control\Power\HibernateEnabled`，写走 `powercfg /hibernate on|off`（唯一受支持方式），检查退出码。超时：读走 powrprof 的 `PowerGetActiveScheme` + `PowerReadAC/DCValueIndex`（秒级、与语言无关，避免解析本地化的 powercfg 输出），写走 `powercfg /change monitor-timeout-ac / standby-timeout-ac`，只动交流电源一侧 |
| `IDisplay` | 读 `EnumDisplaySettings` 枚举全部模式，取同分辨率同色深下的最高刷新率；写 `ChangeDisplaySettingsEx` 只置 `DM_DISPLAYFREQUENCY` 与 `CDS_UPDATEREGISTRY`，返回 `DISP_CHANGE_SUCCESSFUL/RESTART` 都算成功 |
| `StartupItems` | 枚举 HKCU/HKLM 的 `Run` 键与启动文件夹；启用状态看 `StartupApproved` 下的 12 字节值（首字节 bit0 置位即禁用）。开关只写 `StartupApproved`，不碰 Run 键本身。不用 `Win32_StartupCommand` 判断状态——它把已禁用的项也照列 |
| `IFileSystem.FilesOlderThan / TryDeleteFile` | 递归枚举跳过重解析点；删除失败（占用）返回 false 不抛出，任务汇总到手动项 |
| `ISystemRestore` | WMI `root\default:SystemRestore.CreateRestorePoint(desc, 0, 100)`；24 小时内已有还原点时系统会跳过，视为成功 |
| `IStorage` | WMI `root\Microsoft\Windows\Storage`：`MSFT_Partition.GetSupportedSize / Resize`、`MSFT_Disk.CreatePartition`、`MSFT_Volume.Format`；所有调用检查 ReturnValue 与 ExtendedStatus。只读的两个补充方法走别处：`FileSystemOf` 读 `Win32_LogicalDisk.FileSystem`，`LargestFreeExtent` 读 `MSFT_Disk.LargestFreeExtent`，读不到分别返回 null 与 0，不抛异常 |
| `IProcessInfo` | 当前是否管理员；`explorer.exe` 所属用户 SID 与当前进程 SID 比对（HKCU 归属校验） |
| `SystemChecks` | 《01》4.5 的八项只读检查：`Win32_EncryptableVolume`（BitLocker）、`root\SecurityCenter2` 的 `AntiVirusProduct`、`Win32_QuickFixEngineering`（最近补丁时间）、Build 与系统卷容量（还原点占用）、Uninstall 键的 Publisher（OEM 预装）、`BatteryProbe`（电池健康）、`UserChoice` 的 ProgId（默认浏览器）、`RegionInfo`/`TimeZoneInfo`。入参是 `EnvironmentSnapshot?`，为 null 时与机器相关的几项降级为“未知”。不写任何值，因此不经 journal；由检查页按需调用，不进启动探测 |
| `DisplayInfo` | `EnumDisplaySettings` + DEVMODE：取主显示器当前模式，再枚举全部模式找同分辨率同色深下的最高刷新率。不用 `Win32_VideoController.MaxRefreshRate`——那是显卡能力，拿来判断“刷新率有没有拉满”会误报 |
| `BatteryProbe` | 先读 `root\WMI` 的 `BatteryStaticData` / `BatteryFullChargedCapacity` / `BatteryCycleCount`；部分机型固件不响应 `BatteryStaticData`（WMI 报“常规故障”），缺设计容量时回退 `powercfg /batteryreport /xml`，解析 `Batteries/Battery` 下的三个值（`RuntimeEstimates` 里有同名节点，不能按名字全局取），临时文件读完即删 |

所有原生调用集中在 Native 项目，Tasks 只通过接口访问，禁止在任务里直接 P/Invoke。

### 7.1 双语文案

用户可见的字符串一律双语，中英两份并列写在调用点：`L.S("显示文件扩展名", "Show file extensions")`，XAML 侧对应标记扩展 `{local:Loc Zh='检查项', En='Checks'}`（值一律用单引号包起来，否则含逗号的英文句子会被解析器切开）。语言按 `CultureInfo.CurrentUICulture` 定，zh-* 用中文，其余英文；`L.Chinese` 可赋值覆盖，测试用得上。

没有走 .resx 是有意的：这个项目的用户可见文字大多是带插值的整句（任务说明、检测结论、手动步骤），资源文件把它们拆成几百个键之后，漏译和格式串对不上都不会在编译期暴露；并列写法改一句就是改一处，评审时两种语言在同一屏里。

两条约束：**界面逻辑不能比较显示文本**——`DataTrigger` 原先拿 `StatusLabel` 跟 "推荐" 比，换语言后绿底徽标就没了，现在比的是 `ShowRecommendedBadge` 这样的布尔属性；**共用词不能用 `static readonly` 字段缓存**，类型初始化时就定死，`TaskCatalog.BuildFresh()` 换语言后取不到新值，要用属性。

日志与内部异常消息保持中文：它们进的是日志文件，读者是开发者。`software.json` 里中文产品名与安装备注另有 `name_en` / `note_en` 两个字段。

## 8. UI 结构

- `MainWindow`：WPF-UI `FluentWindow`，Mica 背景；顶部一行：返回列表（子页时显示，是唯一的返回入口）、执行记录（有手动项时带数量，`ManualSteps.Collect` 与执行记录页共用一份逻辑）、软件推荐、检查项。
- 页面：`HomeView`（常驻主列表）、`ReportView`（执行记录）、`SoftwareView`、`CheckupView`（检查项）。
- `HomeViewModel`：探测 → `Planner.Build` 得到全部条目 → 按 Module 分组为 `CategoryViewModel`，每条 `TaskItemViewModel` 带 `RunCommand`。执行走 `SessionRunner.Run`，结束后重新 Build 并就地更新（保留执行结果）。左栏第一项是固定的“这台电脑”分类（`IsMachineInfo`），选中它时右栏换成只读的硬件信息列表 `MachineInfo`，头部只留探测状态、汇总、数据盘下拉和“重新探测”。
- `Answers` 只剩 `DataDrive` 与 `CreatePartition`；原问卷选项对应的任务始终列出，`DefaultChecked` 仅用于显示“推荐/可选”徽标。
- “当前 → 目标”是人话：`RegistryEntry.As(label, unsetName, (value, name)...)` 给每个注册表值标含义，`RegistryValueTask.Detect` 据此生成“任务栏搜索样式：搜索框+标签”这样的文字，原始键值走 `DetectResult.Detail` → `PlanItem.Detail`，界面只在悬停时显示。一个 Label 都没标的任务保持原样输出键值。
- 探测完成后首次落在第一个有可执行项的分类；不适用原因单独一行；不适用项可带一个辅助按钮（`HomeViewModel.AuxActionFor`，目前只有桌面被 OneDrive 接管时的“打开 OneDrive 设置”）。
- 共享 `SessionState`（Snapshot、Answers、Plan、PreviousResult）。
- 长操作（探测、执行、重新 Detect）一律在 `Task.Run` 中进行，UI 只订阅 `IProgress`。`Planner.Build` 要跑几十个 `Detect`，绝不能放在 UI 线程上——早期版本正是这样，窗口会整段无响应十几秒。
- 探测只做注册表与 WMI 读取（本机约 0.2 s），不做目录体积扫描；原来的 `ScanLargeItems` 与 C 盘治理页已随范围收窄一起删除。
- 主题：跟随系统深浅色，启动时 `ApplicationThemeManager.ApplySystemTheme()`，之后由 `SystemThemeWatcher.Watch(MainWindow)` 监听切换；`App.xaml` 里的 `Theme="Light"` 只是设计时默认。强调色取系统。字体：Segoe UI Variable / 微软雅黑回退。动画：只用控件自带过渡。

软件目录 `catalog/software.json`（嵌入资源）：

```json
{ "id": "7zip", "name": "7-Zip", "category": "tools", "url": "https://www.7-zip.org/",
  "install_dir": "7-Zip", "installer": "nsis", "custom_path": true,
  "detect": { "uninstall_name": "7-Zip" }, "usages": ["office","dev","gaming","home"] }
```

`installer` ∈ `msi | nsis | inno | electron_user | msix | other`，决定路径提示文案。

推荐安装路径 = `<根目录>\<分类子目录>\<install_dir>`，分类子目录由 `SoftwareCatalog.CategoryDir` 给出（Tools / Browsers / Chat / Office / Media / Dev / Games / Runtimes），根目录默认 `<数据盘>\Applications`。用户改过的根目录与逐项路径存 `software-paths.json`（`{ Root, Overrides: { id: path } }`），下次进页面沿用；把某项改回默认值即自动清掉该项覆盖。

## 9. 权限与安全

- 清单 `requireAdministrator`；启动即提权。
- HKCU 归属校验失败则拒绝运行。
- 所有写操作先 journal，后执行；journal 为 JSON Lines，崩溃不丢。
- 不联网（软件推荐页仅调用 `Process.Start(url)` 交给浏览器）。
- 不收集、不上传任何数据。
- 日志不记录用户名以外的个人信息，不记录环境变量完整值中的凭据类名称（黑名单过滤 `KEY|TOKEN|SECRET|PASS`）。

## 10. 错误处理

| 层 | 策略 |
|---|---|
| 任务内 | 抛出 `TaskFailedException(message, inner)`；Runner 捕获并回滚 |
| 原生层 | Win32 错误转 `Win32Exception`，WMI ReturnValue ≠ 0 转 `StorageException(code, extendedStatus)` |
| UI | 全局 `DispatcherUnhandledException` 写日志并提示"已记录到日志"，不静默吞 |
| 崩溃恢复 | 启动时读 `state.json`，`pendingResume=true` 进入 UC-12 |

## 11. 构建与发布

## 13. 编码规范

- C# 文件作用域命名空间，`Nullable enable`，`TreatWarningsAsErrors` 对 Core/Tasks 开启。
- 任务类命名 `<Module><Name>Task`，文件与 Id 对应。
- 用户可见字符串目前直接写在 C# 与 XAML 里，没有 `Strings.resx`。首版只有简体中文，抽资源文件除了多一层间接没有收益；确定要做多语言时再统一抽取。
- 不使用反射注册任务、不使用动态类型、不引入 IoC 容器（手工组装）。
